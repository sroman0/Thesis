\chapter{Selected eBPF Process-Monitoring Implementations}
\label{appendix_a}

This appendix presents selected excerpts from
\path{pkg/ebpf/c/project.bpf.c}. The purpose is to preserve the implementation
details that best illustrate process monitoring without reproducing the full
eBPF translation unit. Chapter~4 owns the architectural interpretation of the
hooks, their observation boundaries and the shared event-construction
framework. The excerpts below instead show how those decisions appear in the
collector source.

All listings reflect the implementation used for the thesis and are abridged
where repeated initialisation or serialisation calls would obscure the central
mechanism. Omitted statements are marked explicitly. Argument indexes remain
visible when they help demonstrate the binary contract with the user-space
event registry.

\section{Process Creation}
\label{sec:appendix-process-creation}

The \texttt{clone} implementation is a concrete use of the paired-producer
model introduced in Section~\ref{sec:implementation-ebpf-programs}. Entry-side
fields are retained under the current thread and logical event; the return
probe removes that temporary state before constructing the event. Listing
\ref{lst:appendix-clone-pair} keeps the fields that distinguish \texttt{clone}
from the simpler \texttt{fork} and \texttt{vfork} paths.

\begin{lstlisting}[
    language=C,
    basicstyle=\ttfamily\scriptsize,
    caption={Entry/return construction of the \texttt{clone} event
    (abridged).},
    label={lst:appendix-clone-pair}
]
SEC("tracepoint/syscalls/sys_enter_clone")
int tracepoint__syscalls__sys_enter_clone(sys_enter_clone_ctx_t *ctx)
{
    args_t args = {};
    args.args[0] = ctx->flags;
    args.args[1] = ctx->stack;
    args.args[2] = ctx->parent_tid;
    args.args[3] = ctx->child_tid;
    args.args[4] = ctx->tls;
    return save_args(&args, CLONE);
}

SEC("tracepoint/syscalls/sys_exit_clone")
int tracepoint__syscalls__sys_exit_clone(sys_exit_generic_ctx_t *ctx)
{
    args_t args = {};
    if (load_args(&args, CLONE) != 0)
        return 0;
    del_args(CLONE);

    program_data_t p = {};
    if (!init_program_data(&p, ctx, CLONE))
        return 0;

    unsigned long flags = args.args[0];
    long ret = ctx->ret;
    save_to_submit_buf(&p.event->args_buf,
                       &flags, sizeof(unsigned long), 0);
    /* stack, TID pointers and TLS occupy indexes 1--4. */
    save_to_submit_buf(&p.event->args_buf,
                       &ret, sizeof(long), 5);
    return events_perf_submit(&p);
}
\end{lstlisting}

The saved values remain opaque addresses where the syscall exposes pointers;
the collector does not dereference the parent-TID, child-TID or stack fields.
Deleting the entry before submission also ensures that a later invocation on
the same thread cannot consume stale construction state.

The scheduler tracepoint supplies a different form of evidence: both task
objects already exist when the program runs. Listing
\ref{lst:appendix-sched-process-fork} shows the extraction of stable local
process identity used by later correlation. It is included here rather than in
Chapter~4 so that the body can explain the distinction without carrying the
complete serialisation sequence.

\begin{lstlisting}[
    language=C,
    basicstyle=\ttfamily\scriptsize,
    caption={Parent-child evidence collected by
    \texttt{sched\_process\_fork} (abridged).},
    label={lst:appendix-sched-process-fork}
]
struct task_struct *parent =
    (struct task_struct *) ctx->args[0];
struct task_struct *child =
    (struct task_struct *) ctx->args[1];

u32 parent_pid = get_task_host_tgid(parent);
u32 parent_tid = get_task_host_pid(parent);
u32 child_pid = get_task_host_tgid(child);
u32 child_tid = get_task_host_pid(child);
u64 child_start = get_task_start_time(child);

save_to_submit_buf(&p.event->args_buf,
                   &parent_pid, sizeof(u32), 0);
save_to_submit_buf(&p.event->args_buf,
                   &parent_tid, sizeof(u32), 1);
save_to_submit_buf(&p.event->args_buf,
                   &child_pid, sizeof(u32), 2);
save_to_submit_buf(&p.event->args_buf,
                   &child_tid, sizeof(u32), 3);
save_to_submit_buf(&p.event->args_buf,
                   &child_start, sizeof(u64), 4);
\end{lstlisting}

The start time complements the numeric identifiers because a later task may
reuse the same PID. The event still represents one bounded relationship; the
eBPF program does not retain a process tree.

\section{Executable Transitions}
\label{sec:appendix-executable-transitions}

Execution monitoring begins while pathname and argument-vector pointers still
refer to the caller's address space. Listing
\ref{lst:appendix-exec-requests} shows the dedicated syscall tracepoints. The
shared string-array helper limits traversal to 38 entries and also remains
bounded by the event buffer capacity.

\begin{lstlisting}[
    language=C,
    basicstyle=\ttfamily\scriptsize,
    caption={Capturing \texttt{execve} and \texttt{execveat} requests
    (abridged).},
    label={lst:appendix-exec-requests}
]
SEC("tracepoint/syscalls/sys_enter_execve")
int tracepoint__syscalls__sys_enter_execve(sys_enter_execve_ctx_t *ctx)
{
    program_data_t p = {};
    if (!init_program_data(&p, ctx, EXECVE) || !ctx->pathname)
        return 0;

    save_str_to_buf(&p.event->args_buf, (void *) ctx->pathname, 0);
    if (ctx->argv)
        save_str_arr_to_buf(
            &p.event->args_buf,
            (const char __user *const __user *) ctx->argv, 1);
    return events_perf_submit(&p);
}

SEC("tracepoint/syscalls/sys_enter_execveat")
int tracepoint__syscalls__sys_enter_execveat(sys_enter_execveat_ctx_t *ctx)
{
    program_data_t p = {};
    if (!init_program_data(&p, ctx, EXECVEAT))
        return 0;

    int dirfd = ctx->dirfd;
    int flags = ctx->flags;
    save_to_submit_buf(&p.event->args_buf,
                       &dirfd, sizeof(int), 0);
    if (ctx->pathname)
        save_str_to_buf(&p.event->args_buf, (void *) ctx->pathname, 1);
    save_to_submit_buf(&p.event->args_buf,
                       &flags, sizeof(int), 2);
    if (ctx->argv)
        save_str_arr_to_buf(
            &p.event->args_buf,
            (const char __user *const __user *) ctx->argv, 3);
    return events_perf_submit(&p);
}
\end{lstlisting}

The two producers use different schemas because \texttt{execveat} must retain
its directory descriptor and flags. Neither reads the environment array or
waits for a syscall result; their role is to preserve the original request.

After pathname resolution, \texttt{security\_bprm\_check} can identify the
kernel file rather than only the caller's string. A later scheduler tracepoint
confirms replacement of the executable image. Listing
\ref{lst:appendix-exec-kernel-stages} places the essential extraction performed
at these two boundaries side by side.

\begin{lstlisting}[
    language=C,
    basicstyle=\ttfamily\scriptsize,
    caption={Resolved binary identity and successful executable transition
    (abridged from two hooks).},
    label={lst:appendix-exec-kernel-stages}
]
/* security_bprm_check: resolved executable under mediation. */
if (!bprm)
    return 0;
struct file *file = BPF_CORE_READ(bprm, file);
if (!file)
    return 0;

void *file_path = get_path_str(
    __builtin_preserve_access_index(&file->f_path));
if (!file_path)
    return 0;

dev_t s_dev = get_dev_from_file(file);
unsigned long inode_nr = get_inode_nr_from_file(file);
save_str_to_buf(&p.event->args_buf, file_path, 0);
save_to_submit_buf(&p.event->args_buf,
                   &s_dev, sizeof(dev_t), 1);
save_to_submit_buf(&p.event->args_buf,
                   &inode_nr, sizeof(unsigned long), 2);
/* filename, argc and envc occupy indexes 3--5. */

/* sched_process_exec: replacement has completed. */
struct linux_binprm *completed_bprm =
    (struct linux_binprm *) ctx->args[2];
if (!completed_bprm)
    return 0;
const char *filename = BPF_CORE_READ(completed_bprm, filename);
if (!filename)
    return 0;

save_str_to_buf(&p.event->args_buf, (void *) filename, 0);
events_perf_submit(&p);
\end{lstlisting}

These statements come from independent programs and do not imply that the
collector joins the two records in kernel space. Their schemas deliberately
preserve mediation and successful transition as separate observations.

Failure requires the opposite outcome test. The entry program retains the
request, and the exit program emits only a negative result. Listing
\ref{lst:appendix-process-execute-failed} contains the return-side logic moved
from Chapter~4.

\begin{lstlisting}[
    language=C,
    basicstyle=\ttfamily\scriptsize,
    caption={Return-side emission of failed executable transitions
    (abridged).},
    label={lst:appendix-process-execute-failed}
]
args_t args = {};
if (load_args(&args, PROCESS_EXECUTE_FAILED) != 0)
    return 0;
del_args(PROCESS_EXECUTE_FAILED);

if (ret >= 0)
    return 0;

program_data_t p = {};
if (!init_program_data(&p, ctx, PROCESS_EXECUTE_FAILED))
    return 0;

int operation = (int) args.args[0];
int dirfd = (int) args.args[1];
const char *pathname = (const char *) args.args[2];
int flags = (int) args.args[3];

save_to_submit_buf(&p.event->args_buf,
                   &operation, sizeof(int), 0);
save_to_submit_buf(&p.event->args_buf,
                   &dirfd, sizeof(int), 1);
if (pathname)
    save_str_to_buf(&p.event->args_buf, (void *) pathname, 2);
save_to_submit_buf(&p.event->args_buf,
                   &flags, sizeof(int), 3);
save_to_submit_buf(&p.event->args_buf,
                   &ret, sizeof(long), 4);
return events_perf_submit(&p);
\end{lstlisting}

Removing the saved arguments before the sign test makes both outcomes consume
their temporary entry. Successful execution is represented by the scheduler
event; only failure reaches this producer's submission call.

\section{Credential Transition Filtering}
\label{sec:appendix-credential-transition}

The selected credential excerpt illustrates early semantic filtering rather
than the generic UID admission described in Chapter~4. The
\path{security_task_fix_setuid} hook receives both the existing and
proposed credentials. Listing~\ref{lst:appendix-fix-setuid} shows that an event
is serialised and submitted only when at least one monitored UID field changes.

\begin{lstlisting}[
    language=C,
    basicstyle=\ttfamily\scriptsize,
    caption={Change-only capture in
    \texttt{security\_task\_fix\_setuid} (abridged).},
    label={lst:appendix-fix-setuid}
]
u32 old_uid = BPF_CORE_READ(old_cred, uid.val);
u32 new_uid = BPF_CORE_READ(new_cred, uid.val);
u32 old_euid = BPF_CORE_READ(old_cred, euid.val);
u32 new_euid = BPF_CORE_READ(new_cred, euid.val);
u32 old_suid = BPF_CORE_READ(old_cred, suid.val);
u32 new_suid = BPF_CORE_READ(new_cred, suid.val);
u32 old_fsuid = BPF_CORE_READ(old_cred, fsuid.val);
u32 new_fsuid = BPF_CORE_READ(new_cred, fsuid.val);

if (old_uid == new_uid &&
    old_euid == new_euid &&
    old_suid == new_suid &&
    old_fsuid == new_fsuid)
    return 0;

save_to_submit_buf(&p.event->args_buf,
                   &old_uid, sizeof(u32), 0);
save_to_submit_buf(&p.event->args_buf,
                   &new_uid, sizeof(u32), 1);
save_to_submit_buf(&p.event->args_buf,
                   &old_euid, sizeof(u32), 2);
save_to_submit_buf(&p.event->args_buf,
                   &new_euid, sizeof(u32), 3);
/* saved and filesystem UIDs occupy indexes 4--7. */
save_to_submit_buf(&p.event->args_buf,
                   &flags, sizeof(int), 8);
return events_perf_submit(&p);
\end{lstlisting}

The comparison removes no-change invocations before transport, while the
event that remains preserves both sides of the proposed transition. It does
not turn the mediation hook into confirmation that the new credentials were
installed; that distinction remains owned by the architectural discussion in
Section~\ref{subsubsec:implementation-identity-credentials}.

These excerpts cover the process mechanisms that benefit most from source-level
inspection: entry/return state, stable lifecycle identity, bounded user-memory
capture, resolved executable evidence, explicit outcome selection and
change-only credential emission. The remaining process hooks reuse these
patterns or perform direct bounded serialisation and are therefore left in the
repository rather than reproduced here.
